# RightLingo

Chrome 原生右键菜单翻译插件。`Translation, right in your context menu.`

当前进度：**v0.8.0 —— 设置页第二档**（一级摘要长度三档、Google 翻译项显隐）。

## 目录结构

```text
rightlingo/
├── manifest.json    # 扩展清单：MV3、权限、后台（module）、内容脚本
├── background.js    # Service Worker：菜单管理 + 翻译调度（缓存/去重/过期丢弃）
├── content.js       # Content Script：监听选区，mouseup 立即上报 + 占位符信号
├── translate.js     # 翻译引擎（独立模块，以后换引擎只改这里）
├── display.js       # 菜单显示规则（纯函数：显示宽度、截断、断行，可用 node 单独验证）
├── settings.js      # 设置默认值与读取（options 页与后台共用）
├── options.html/js  # 设置页（工具栏图标右键 → "选项"打开）
├── offscreen.html/js# 隐藏的剪贴板执行页（SW 写不了剪贴板，由它代劳，官方 offscreen 模式）
├── icons/           # 扩展图标：icon.svg 为设计源文件，icon16/32/48/128.png 由脚本导出
├── tools/           # 开发脚本（export-icons.sh：SVG → 四尺寸 PNG，用无头 Chrome 渲染）
└── docs/            # PRD 与文档
```

## 数据流

```text
选区开始变化 → content.js 发 selection-reset → 菜单立即切到"译文：正在翻译…"（防旧内容残留）
选区结束（mouseup 立即 / 键盘 150ms 去抖）→ content.js 发选中文本
        → background.js 查缓存 / 调 translate.js（Google gtx 端点，auto → zh-CN）
        → 菜单标题更新为"译文：xxx"；失败显示"译文：（翻译失败）"
用户右键 → 菜单三种状态：当前译文（正常）/ 正在翻译…（在途）/ 上一次内容（异常信号）
点击译文项 → SW 唤醒 → 取最近译文（storage.session 命中 / 现场重翻）→ offscreen 文档写入剪贴板
```

## 翻译引擎说明

- 使用 `translate.googleapis.com/translate_a/single`（`client=gtx`），即 Google 翻译网页版
  所用的公开端点，与沉浸式翻译等扩展的做法相同；非官方、无 SLA，但已被广泛使用多年。
- 域名在 manifest 中以 `host_permissions` 声明，后台可直接跨域调用。
- `translate.js` 是独立模块：以后换 Chrome 内置 AI / DeepL / LLM 只改这一个文件。
- 源语言自动识别；检测结果为中文时显示"（原文已是中文）"，暂不做中→英（PRD §9）。
- 送翻译的字符数随"二级菜单行数"变化：只翻译**够填满菜单**的量（约 `行数 × 104` 源字符，已计入英→中压缩——每行显示 52 格，译文显示宽约为源的 0.5，故源字符预算按 2 倍估；这样选 5 行能真正铺满 5 行而非约 3 行），不整段送译，避免长选文拖慢响应。原文上限仍 2000 字符（用于存储与"在 Google 翻译中翻译"跳转），超长原文完整阅读走该按钮。
- 预算截断**只在词边界处切**（`budgetSlice`）：直接按字符硬切会把英文单词拦腰切断（如 `after`→`aft`），残词被逐字翻译出离谱结果（"`aft`"→"船尾"）。详见下方"长文本显示规则"。

## 长文本显示规则

- 译文宽度 ≤ 74 格（一级上限 80 − 前缀 6）：**一级菜单直显完整译文**，无子菜单
- 超过则一级显示摘要（自动带 `…` 和子菜单箭头 ▶，箭头由 Chrome 根据可见子项自动添加），
  完整译文分行进二级菜单：
  - 每行一个菜单项（菜单标题不支持换行，这是唯一的多行方式），行宽 ≤ 52 格（刻意压在 macOS 系统菜单 ~400px 中间省略阈值以内，否则每行译文会被从中间抠掉一段），最多由"二级菜单行数"设置控制（**默认 5，最多 10 行**）
  - 断行优先在空格处（英文单词不切半）；连续中文/长 URL 按宽度硬切
  - 截断提示：一级标题末尾的 `…`，以及二级菜单**最后一行行末**的 `…`（仅译文超出显示行数时拼上，不另起一行，表示"还有更多"）；完整译文点二级菜单底部的 **复制完整译文**（或任意译文行）即可拿到
- 二级菜单底部依次为：分隔线 → **在 Google 翻译中翻译**（新标签页打开网页版并自动翻译原文，
  长文本的完整阅读出口）→ 复制完整译文
- 行数刻意偏少：菜单里只管预览，完整阅读交给网页版
- 常量都在 `background.js` 顶部（`PREVIEW_MAX_WIDTH` / `SUBMENU_MAX_LINES` / `SUBMENU_LINE_WIDTH`），可调
- `display.js` 是纯函数，可用 node 单独验证断行效果（不依赖 Chrome）

## 设置（v0.7.0）

入口：工具栏扩展图标右键 → **选项**（不往右键菜单里塞"设置"项，保持菜单纯净）。
存 `chrome.storage.sync`（跟随 Chrome 账号漫游），改动**即时生效**，无需刷新页面。

| 设置 | 说明 |
|---|---|
| 目标语言 | 支持 Google 翻译全部 130+ 种语言（按常用语言与 A-Z 拼音分组，默认简体中文）。选中文本本身就是目标语言时提示而不翻译，支持简繁互转 |
| 二级菜单行数 | 1–10 行，默认 5（槽位池固定 10 个，按设置控制可见数） |
| 词典模式 | 默认开启；关闭后单词也按普通句子翻译显示 |
| 一级菜单摘要长度 | 短/中（默认，约 40 个汉字）/长 三档，决定"一级直显 vs 摘要+二级"的分界 |
| "在 Google 翻译中翻译"项 | 可从二级菜单隐藏（默认显示） |
| 点击译文时复制 | 仅译文（默认）/ 原文 + 译文（两行拼接，背单词/记笔记用） |

## 词典模式（v0.6.0）

- 选中单词时，翻译请求自动附带词典参数（`dt=bd`，即网页版 Google 翻译"词典"标签的同源数据）
- 接口返回词典数据 → **词典模式**：一级菜单仍显示主译文（右键即读），二级菜单按词性分组展示多个释义，
  每个词性一行、最多与"二级菜单行数"一致（默认 5，最多 10 行），超出宽度以 `…` 截断：

  ```text
  译文：标志性的
     ├ 形: 标志性的；偶像的；偶像般的…
     ├ 名: 偶像；偶像形象
     ├ ─────────────
     ├ 在 Google 翻译中翻译      ← 同时是"看完整词典和例句"的出口
     └ 复制完整译文
  ```

- 接口没返回词典数据（短语/句子）→ 自动回退普通句子翻译；是否进词典模式由接口数据决定，不做脆弱的"单词判断"
- 词性标签做英文→中文映射（noun→名、adjective→形…），映射不到的原样显示
- 复制行为不变（点击仍复制主译文）；词典数据不进 storage.session（点击复制用不到它）

## 复制行为（阶段五）

- 点击**任何**译文相关菜单项——一级译文、二级任意行、`复制完整译文`——复制的都是**菜单里显示的译文**（长选文只翻译了填满菜单的前缀，故复制的也是这部分；要看/复制完整原文去"在 Google 翻译中翻译"）；`在 Google 翻译中翻译` 除外（它跳转网页）
- 复制没有视觉反馈（菜单随点击关闭，扩展不弹任何提示），粘贴即可验证
- 最近一次译文存放在 `chrome.storage.session`：点击会唤醒 SW（内存缓存已清空），命中就立即复制，对不上（如浏览器重启过）就现场重翻一次再复制
- 中文选区点击复制 = 复制原文本身

## 如何加载扩展

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本项目根目录（`rightlingo/`）
4. 在工具栏拼图图标里把 RightLingo 固定出来，方便管理

## 如何验证阶段二

1. `chrome://extensions` 刷新 RightLingo（这次改了 manifest，必须刷新），确认无报错
2. 打开普通网页（`chrome://` 页面和商店页不运行内容脚本），选中英文单词如 `iconic`
3. 右键 → 菜单显示 `译文：标志性的`（短译文一级直显）
4. 选中一段中文 → 右键 → `译文：（原文已是中文）`
5. 断网后选中新文本 → 右键 → `译文：（翻译失败）`
6. 老场景仍要过：快速"选中 A → 右键 → 选中 B → 立刻右键"，菜单应为 B 或"正在翻译…"，绝不应是 A

### 查看日志

正常路径不打日志。出错时会以 `[RightLingo]` 前缀输出到控制台，用于诊断：
后台错误在 `chrome://extensions` → RightLingo → 「Service Worker」→ inspect 查看
（翻译失败、复制失败、菜单创建/更新失败会记录；页面控制台保持安静）。

## 关于菜单能显示多少字

实测（Chrome 141 / macOS）：扩展菜单标题**没有字符数硬上限**——菜单按内容撑宽（系统有最大宽度），超出才按像素截断加 `…`。
插件自己控制"显示宽度上限"：`background.js` 里 `PREVIEW_MAX_WIDTH`（当前 80 ≈ 40 个汉字；CJK/全角按 2 格计，其余按 1 格计）。想调就改这一个数。
正式前缀 `译文：` 占 6 格。

- 改了扩展文件 → `chrome://extensions` 点 RightLingo 卡片上的**刷新**按钮
